# C4-lite - Prototype Lab Concept

## System context

```mermaid
flowchart LR
  Creator[Creator / Playtester] --> Lab[MCL Prototype Lab]
  Agent[Coding Agent] --> Lab
  SSoT[Confluence MLOA / Jira MCL] -. source refs only .-> Lab
  Assets[Local / third-party / generated assets] --> Registry[Asset Registry]
  Registry --> Lab
  Lab --> Adapter[Runtime Adapter - EXCEPTION GRANTED / IMPLEMENTATION PENDING]
  Adapter --> Local[Local playable runtime]
  Web[DYAI2025/MC_legends Web] -. no runtime dependency .- Lab
```

## Containers / modules

```mermaid
flowchart TB
  Catalog[Experiment Catalog]
  Contracts[Experiment Contracts + Schemas]
  Registry[Asset Registry]
  CreatureFX[Creature / FX Concept Profiles]
  LocalLogic[Experiment-local Mechanics]
  Shared[Shared Mechanics - only after demonstrated reuse]
  Debug[Debug / Tuning Harness Contract]
  Adapter[Runtime Adapter - implementation pending]
  Validate[Validation Tooling]

  Catalog --> Contracts
  Catalog --> LocalLogic
  Catalog --> Registry
  CreatureFX --> Registry
  LocalLogic -. promote after >=2 uses .-> Shared
  Contracts --> Validate
  Registry --> Validate
  CreatureFX --> Validate
  LocalLogic --> Adapter
  Shared --> Adapter
  Debug --> Adapter
  CreatureFX --> Adapter
```

Key rule: the adapter isolates runtime boot/scene/input/asset/debug/visual integration. It is not a promise that all game logic will be engine-independent.

## Visual concept boundary

The runtime foundation must be visually capable enough to evaluate source-linked creature concepts, but it must not become a final creature framework. `concepts/creatures/*.json` supplies data-driven visual profiles for Mugosh, Flammenwolf, Veras and Zhalm; the runtime may render them with primitives first and later replace geometry through stable asset IDs.
